# govengers/mail: design

Status: v0, first cut. Decisions are numbered `M`; a later change gets a new number, never a rewrite.

`govengers/mail` is how a govengers service sends transactional mail: a message type, transports for SMTP and Resend, MJML templates per locale, observability adapters, and an adapter that sends from a govengers/jobs job. Profile `library`, Apache 2.0, Go 1.26; govengers/standards apply.

## 1. The model

```
service        templates.Render(name, locale, data) -> *Message; message.To = ...; mailer.Send(ctx, message)
  |       or   sender.Template(name, locale, data, envelope) -> Payload; store.Enqueue(ctx, tx, jobsadapter.Kind.New(payload, nil))
  |            (the job renders the mail when it runs, M18)
Mailer         copy, default From, Validate, Observer
  |
Transport      smtp | resend | logmailer | mailtest.Recorder   (oteladapter wraps any of them)
```

Mail is sent where the delivery belongs: directly for a mail the caller waits for, rendered where the data is; through a job for a mail that must follow a committed change, rendered when the job runs from a payload that names the template and carries its data (M18).

## 2. Decisions

| ID | Decision |
|----|----------|
| M1 | Module `github.com/govengers/mail`. The root module depends on the standard library only in its core and transports; `prometheusadapter` (client_golang) and `oteladapter` (OpenTelemetry API) live in the root module like govengers/jobs' adapters, and module graph pruning keeps them out of a consumer that does not import them. `jobsadapter` and `cmd/mailgen` are nested modules: they pull in govengers/jobs (pgx, auth) and the MJML engine, which a consumer of the core must never inherit. |
| M2 | One `Message` struct with `From`, `To`, `ReplyTo`, `Subject`, `HTML`, `Text`, `Headers`, `Attachments`, `IdempotencyKey`, with JSON tags: it is also the job payload (M12), so field renames must not break a rolling deploy. No Cc and Bcc in v0: transactional mail goes to one person; add them when a service needs them. |
| M3 | `Transport` is the one-method interface every transport implements; `Mailer` wraps a transport and is itself a `Transport`. The Mailer copies the message (a caller's message is never changed), fills in `Options.From`, validates and reports to the `Observer`. Validation lives in the Mailer so every transport gets it once, and transports used directly still never see a message that would inject a header. |
| M4 | Errors: `ErrPermanent` marks failures a retry cannot fix, `ErrInvalidMessage` (always with `ErrPermanent`) marks validation failures. A misconfigured transport is never permanent: an SMTP 5xx to the greeting, STARTTLS or AUTH, an SMTP 530 (authentication required) to MAIL or RCPT and a Resend 401, 403 or 404 are temporary, because a rotated password or a wrong key would otherwise kill every queued mail on its first attempt; the job's backoff retries them until the configuration is fixed. The smtp transport greets explicitly before MAIL so a refused EHLO is classified as a connection failure. Transports translate their protocol's errors (SMTP 5xx to MAIL, RCPT or DATA, Resend 4xx except 401, 403, 404, 408, 429 and a 409 for a key in flight) and keep the dependency's error out of the chain (LIB-010); only context errors are wrapped, so callers can match `context.Canceled`. |
| M5 | Validation at the trust boundary: every address parses with `net/mail` and its addr-spec goes into the SMTP envelope unchanged (no quoted local part that needs its quotes, found by a net/mail round trip, so `"a@evil.example"@corp.example` and `"a..b"@corp.example` are rejected too; no domain literal: net/mail unquotes and net/smtp writes `RCPT TO:<%s>` unescaped, so `"a@evil.example> NOTIFY=NEVER"@corp.example` would redirect the mail; the smtp transport validates on its own too, for a handler that bypasses the Mailer), the subject and header values are one line, header names are field names and cannot set a field the transports write (`From`, `To`, `Subject`, `Content-Type`, ...), attachment file names hold no path or line break, attachment content types parse and hold no line break, the idempotency key is at most 256 bytes (Resend's limit). |
| M6 | `smtp` uses `net/smtp`, not a third-party client: the standard library covers dialing, STARTTLS and AUTH PLAIN, and the MIME writer is ~150 lines of `mime/multipart` and `quotedprintable`. STARTTLS is the default and mandatory when chosen (no downgrade when the server does not offer it); implicit TLS and none are explicit choices; AUTH without TLS is refused at `New` unless the server is on localhost (net/smtp's own rule, surfaced early). One connection per message: no pool, no pipelining; a service that sends thousands of mails a minute should use the API transport. A context cancel interrupts any network wait through the connection's deadline (`context.AfterFunc`). A failed QUIT after an accepted DATA is success. |
| M7 | SMTP is at least once: a connection that breaks after the server accepted DATA but before the reply arrived looks like a failure, and a retry delivers again. SMTP has no idempotency key; the docs say so and point to the Resend transport for exactly-once within 24 hours. The Message-ID is the SHA-256 of `IdempotencyKey` (hex) at the sender's domain when a key is set, random otherwise, so a retried job's copy carries the same Message-ID and receivers that deduplicate on it drop it (JOB-003). |
| M8 | `resend` uses `net/http` and the documented POST /emails body; `Message.IdempotencyKey` goes into `Idempotency-Key`. No SDK dependency. The error body (`name`, `message`) is part of the returned error text; the classification uses the status and, for 409, the name. Rate limits (429) are temporary; the job's backoff does the waiting, the transport never sleeps or retries itself. |
| M9 | Templates: MJML is compiled at build time by `cmd/mailgen` and the HTML is committed; `mailgen -check` is the drift check (it compiles in memory and fails on a differing, missing or orphaned `.html`). The engine is `github.com/preslavrachev/gomjml` (native Go, no Node), pinned by the mailgen module's go.mod, so a mailgen version always writes the same bytes and the check runs in any Go CI in milliseconds. Rejected: `bunx mjml` (needs Bun or Node in every CI that runs the check), `mjml-go` (the official engine in WebAssembly, megabytes and seconds of start-up for a build step, last released 2025). The engine sits behind one call in mailgen; swapping it is a mailgen release. |
| M10 | Shared layout at the MJML level: `_layout.mjml` (or `_layout.<locale>.mjml`, falling back by locale) is a whole document with `<!-- mail:content -->` and optionally `<!-- mail:head -->`; a body source may start with `<mj-head>` for its own `mj-preview` or `mj-title`. A source that is a whole `<mjml>` document skips the layout. `mj-include` is not supported because neither Go engine resolves it; the marker keeps the layout a valid MJML document that opens in MJML's editor. |
| M11 | Runtime rendering: HTML with `html/template` (contextual escaping), the plain-text part and the subject with `text/template` from `<name>.<locale>.txt` (`{{define "subject"}}`; the subject is collapsed to one line, the text trimmed). Both use `missingkey=error`. `html/template` drops HTML comments, which would delete Outlook's conditional comments that MJML's output depends on, so every comment is cut out before parsing and written back verbatim by a template function; an action inside a comment is a load error (gomjml puts an `mj-raw` between sections inside those comments, so loops belong inside one `mj-text`). Escaping errors surface at `NewTemplates` through a dry run, not at the first send. |
| M12 | Locales: `<name>.<locale>.html|txt`, tags like `en`, `de-AT`, `pt_BR` normalized to lower case with hyphens. `Render` falls back from the most specific tag to its parents, then to `DefaultLocale`; every template must exist in the default locale, checked at `NewTemplates`. The plain-text layout falls back by locale to `_layout.txt` but never to another language's layout. |
| M13 | Link validation: after rendering, every `href`, `src`, `background`, `action`, `formaction` and `poster` attribute and every `srcset` candidate of a start tag (also inside conditional comments) must be an absolute `http` or `https` URL with a host, or `mailto`; otherwise `ErrUnsafeLink`. Relative links break in every mail client, `javascript:` and `data:` must never ship, and `html/template`'s `#ZgotmplZ` for a filtered URL is caught too. Text nodes are not scanned (data there is escaped, so a user name containing `href=` cannot fail a render). CSS `url()` is not checked. |
| M14 | Observer per LIB-012: `Observer.SendFinished(*Outcome)` with `Result` sent, invalid, rejected or failed; `prometheusadapter` exports `<namespace>_mail_sends_total{result}` and `<namespace>_mail_send_duration_seconds{result}`, every result pre-initialised. Tracing is a transport decorator (`oteladapter.NewTransport`) because a span must wrap the call; it records recipients and attachment counts, never addresses or subjects (personal data). A failure sets the status to error with a fixed description (`permanent failure`, `temporary failure`) and `mail.permanent`; the error text is not recorded because SMTP replies and Resend validation messages quote the rejected address. |
| M15 | `jobsadapter.Handle(worker, kind, transport)` registers a handler for a `jobs.Kind[mail.Message]`: `jobsadapter.Kind` (`mail.send` on the queue `mail`, jobs' default attempts and backoff) or one the service declares for another queue or backoff. A kind is a stateless value, so a shared package-level default is safe and saves every service the same declaration. The payload is the rendered message (decided at enqueue, so a template change after enqueue cannot change a queued mail and the handler needs no template data). The job ID becomes `IdempotencyKey` unless the message has one; `ErrPermanent` becomes `jobs.Permanent`. govengers/jobs caps payloads at 256 KiB, so large attachments go through blob storage. Known cost, kept for v0: this deviates from JOB-006 (payloads are references), and the payload holds the rendered bearer links (password reset, confirmation) in clear text in the jobs table and its admin listing until the sweep removes the finished job; a reference payload rendered in the handler is the alternative if that is not acceptable. Superseded by M18. |
| M16 | `mailtest` carries the fakes a service's end-to-end suite needs: `Recorder`, a loopback SMTP server (STARTTLS, implicit TLS, AUTH PLAIN, reply overrides) and a Resend fake that honours idempotency keys like the real API, plus `Parse` (RFC 5322 back to a `Message`) and `Links`. `TLSConfigs` borrows net/http/httptest's test certificate, so no key is generated per test. |
| M17 | Tests: no network beyond loopback servers the test starts, no Docker, no database, no sleeps. jobsadapter runs the real jobs worker (`RunDue`) on an in-memory Store; the enqueue-in-transaction guarantee is govengers/jobs' own tested contract. The end-to-end suite builds mailgen, compiles the testdata, renders and sends through smtp and resend to the fakes, and compares the fresh HTML with the committed testdata. |
| M18 | Supersedes M15's payload. The payload of a mail job is `jobsadapter.Payload`: `Template`, `Locale`, `Data` (the template data as JSON) or `SealedData`, and `Message` as the envelope (To, From, ReplyTo, Headers, Attachments, IdempotencyKey). The handler renders when the job runs, so no rendered body and no bearer link sits in the jobs table or its admin listing (JOB-006: payloads are references). An empty `Template` sends `Message` as it is, for a caller that renders a mail without secrets itself. The pieces live on `jobsadapter.Sender` (`New(&Options{Transport, Templates, Sealer, Resolve})`, `Template`, `Handle`, `Handler`); the package functions `Handle` and `Handler` are gone (unreleased, no shim). `Template` checks the template name (`Templates.Has`) for every template, so a typo fails in the caller's transaction instead of retrying through every attempt, and copies the envelope's `To`, `Headers` and `Attachments`, so a caller that reuses one envelope for a batch does not change the mails already built. (1) Data is stored as JSON. A template without a resolve function (3) renders it decoded with `UseNumber`, so it sees the JSON form (field names as JSON keys, numbers with every digit), and `Template` renders that form once at enqueue, so a missing key or an unsafe link fails in the caller's transaction as M15's render at enqueue did. The JSON form is not the caller's type: a zero number is true in `{{if}}` (`json.Number` is a string), `gt` and `lt` against an integer literal fail, a struct's JSON tags rename its fields, and methods and `time.Time` are gone. A template that needs the typed data gets a resolve function that decodes the JSON into the application's type, so it sees the same data as with `templates.Render`. (2) Secrets in the data: `Options.Sealer` (`Seal(plaintext, associatedData)`, `Open(sealed, associatedData)`, the method set of govengers/events' Sealer, E20; no import of auth) seals the whole data of every template mail, bound by the associated data `["govengers_mail", template, locale, to]`, so sealed data copied into a job for another template, locale or recipient does not open; a job with the same three accepts it (a replay to the same person), because the associated data is fixed before the job has an ID. The whole data, not chosen fields: the names in it are personal data too, and one rule needs no per-field markup. (3) The simpler alternative is a reference: the data carries an ID (of a reset request), and `Options.Resolve`, a map from template name to `ResolveFunc(ctx, data json.RawMessage) (any, error)`, returns the template data when the job runs; it can end the job with `jobs.Permanent` or `mail.ErrPermanent` when the token was used or revoked, so a stale link is never sent. Per template, so the templates that carry their own data keep the render at enqueue; one kind has one handler, so a second Sender is no way out. A template with a resolve function is not rendered at enqueue (the referenced row may exist only in the caller's uncommitted transaction). (4) Retries: a worker that cannot render yet retries (no Templates or Sealer, `ErrTemplateNotFound` because an older replica claimed a job of a template only the newer one has, a sealing key it does not hold, a resolve error); data that does not decode or render is permanent. A tampered sealed value therefore retries until the job is dead; telling it from a missing key would need the Sealer's cooperation. A template whose data changes incompatibly gets a new name, like a kind (JOB-006), because jobs of the old data may still be pending. The handler's error text is stored as the job's last error and listed by the admin API, so no error on this path quotes rendered data (M19), and the docs of `Sealer` and `ResolveFunc` say their error text is stored too. (5) Rendering at send time means a template change after enqueue changes a queued mail, the opposite of M15; for transactional mail that is the wanted behaviour (a fixed typo reaches the queued mails). The cost: the idempotency key stays the job's ID while the body is rendered per attempt, so with resend a retry after a delivered attempt whose reply was lost, rendering another body (changed data behind a resolve function, a deployed template change), is refused with 409 `invalid_idempotent_request`, which is permanent: the job is dead although the mail went out once. Accepted and documented; treating that 409 as delivered would hide a real key collision. (6) Attachments come from the envelope only. A large file belongs in blob storage and the mail links to it; a service that must attach it wraps `Sender.Handler` and loads the file into `job.Payload.Message.Attachments` before it calls the handler (attachments are not in the associated data). |
| M19 | Supersedes M13's error text. `ErrUnsafeLink` names the template and the link's position (`link 2 in reset.en`), never the link: a rendered link can carry a bearer token, and `Render`'s error ends up in the caller's logs and, through jobsadapter, in the job's last error and its admin listing (M18). For the same reason a template execution error keeps text/template's location and failing action (`template: invite.en:1:11: executing "invite.en" at <.Links>`) and drops its reason, because some reasons print the value (`range can't iterate over <value>`, `eq`'s `non-comparable type <value>`, `index out of range`); a missing key's reason names only the template's field and is kept. The wrapped `text/template.ExecError` is not kept either, its text holds the reason. `Templates.Has(name)` reports whether a template exists, so jobsadapter checks a name without rendering. |

## 3. Not in v0, and when to add it

- Cc, Bcc, inline images (`cid:`): when a service needs them.
- SMTP connection pooling and pipelining: when a service sends more than the per-message handshake allows; until then use the Resend transport for volume.
- More transports (SES, Postmark): as subpackages implementing `Transport`, when a service needs one.
- A wide-event adapter: the Observer carries everything; add `wideeventadapter` when a service wants mail fields on the request's event.
- Template functions (`Funcs`): data comes preformatted in v0; add an option when formatting in templates is needed in more than one service.
- Bounded templates for user-edited bodies: v0 templates are code, written by developers. A tenant-editable template needs a sandboxed renderer (work budget, node allowlist) and is a separate feature.
